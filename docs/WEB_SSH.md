# 管理后台 Web SSH

启用后，管理员可从 `/admin/terminal` 在浏览器中连接其他 SSH 主机。连接由博客
Node.js 进程中转，不会给浏览器开放博客服务器自身的 Shell。

## 启用

在生产环境变量中设置：

```dotenv
WEB_SSH_ENABLED=true
# 只有需要连接内网或回环地址时才填写，逗号分隔且精确匹配。
WEB_SSH_ALLOWED_HOSTS=10.0.0.8,git.internal.example
```

公网主机默认可以连接；解析到回环、RFC1918 私网、链路本地、IPv6 ULA，或云元数据
地址的主机会被拒绝，除非主机名或 IP 明确出现在 `WEB_SSH_ALLOWED_HOSTS`。不要使用
`*`，除非你明确接受管理员账号被攻破后访问整段内网的风险。

## 安全边界

- 页面和全部接口仅允许已完成登录流程的 `admin` 使用。
- 每次连接必须提供并匹配 SHA256 主机密钥指纹。首次尝试只返回观察到的指纹，不会
  继续认证；请通过可信渠道核对后再连接。
- 密码、私钥和私钥口令不写数据库、不进入审计日志；成功连接后浏览器立即清空输入。
- 每位管理员最多两个活动连接，全站最多八个；空闲 30 分钟关闭，最长保留 8 小时。
- 管理员的连接与主动断开会写入审计日志，但只记录目标、用户名和主机指纹。
- 生产环境必须使用 HTTPS；反向代理应关闭 SSE 缓冲，并允许长连接。

当前实现使用同一 Node.js 进程内的短期会话，因此生产环境应保持单实例运行。若以后
横向扩容，需要把终端会话固定到创建它的实例，不能通过普通轮询负载均衡随机分发。
